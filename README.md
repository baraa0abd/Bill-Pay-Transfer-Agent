# بكلمة — Bill Pay & Transfer Agent

Type or say one sentence in Iraqi Arabic, like «ادفع الكهرباء» or «دز خمسين ألف لأحمد», and the agent works out what you mean, asks when it isn't sure, shows a card you can read, and only then pays. It runs against a **mock wallet**, so no real money moves.

**For judges:** [Problem & users](PROBLEM.md) · [Disclosure](DISCLOSURE.md) · [Failure modes](FAILURE_MODES.md) · [Architecture](ARCHITECTURE.md) · [Dev eval](eval/report.md) · Held-out: `eval/report-heldout*.md`

## Results so far (held-out v1, local laptop, no cloud)

| Test set | Rule parser | Local LLM alone (`qwen3.5:4b`) | **Full system** (LLM + checks + rule fallback) | Wrong payments |
|---|---|---|---|---|
| Development, 68 requests | 68/68 | 67/68 | **68/68** | **0** |
| **Held-out** v1, 64 unseen requests, first blind run | 20/64 | 39/64 | — | **0** |
| Held-out v1 after fixing what it revealed (no longer blind) | 49/64 | 46/64 | 48/64 | **0** |

Each case runs three times on a fresh database and passes only if all three pass. The held-out wallet and requests were generated by the local model and frozen before tuning; 19 objectively wrong labels were corrected by rule and marked as AI corrections. The blind run is the honest held-out score ([reports](eval/report-heldout-v1-ollama.md)). It exposed real issues that were then fixed generally, not per case: the Arabic لـ+ال contraction, unknown verbs (ارسل، انطي، بعث), and a model that dropped a typed amount. Current reports: [dev](eval/report-ollama-system.md), [held-out v1 post-fix](eval/report-heldout-v1-postfix-ollama-system.md). Because v1 was used to find fixes it is no longer blind; a **fresh held-out set** is generated with a free hosted model and frozen before the MVP (see *Data and evaluation* below). A second generated held-out set (v2) was discarded as unusable (non-Iraqi and invented words). 256 automated tests pass; the 4-flow demo rehearsal passes on the generated wallet with the local model.

Not done yet: native-speaker hand editing of the held-out requests ([AI review notes](data/REVIEW.md)), real-user interviews ([PROBLEM.md](PROBLEM.md)), voice with real audio, a hosted-model comparison.

## 60-second demo

Start with `./make.ps1 run` (demo faults: set `$env:DEMO_MODE='true'` first) and open http://localhost:8000.

| # | Type | What to point at |
|---|---|---|
| 1 | `ادفع الكهرباء` | It **asks** national grid or generator, instead of guessing. Pick one. The card shows the biller, the account, the amount in digits **and words**, the 250 IQD fee, the balance before and after, and a 2-minute expiry. Press **أكد**. The receipt arrives and the balance on the right updates. |
| 2 | `دز خمسين ألف لأحمد` | Several Ahmeds, each with a masked phone, so it **asks which one**. Pick one, then press **إلغاء**. Nothing was debited. |
| 3 | An amount above the balance, e.g. `دز نص مليون لخالو` | An honest refusal: «you need 500,250 IQD with the fee, and your balance is …». No card is offered. |
| 4 | Pick **انقطاع الرد بعد الدفع** in the sidebar, then pay anything | The response is lost *after* the wallet committed. The agent retries with the **same** idempotency key, and the wallet replays the stored result instead of paying again. The receipt says so («…عدناها بنفس رقم الطلب — انخصم مرة وحدة بس»), and the balance drops **once**. |

The badge in the header says who understood the request: **Ollama**, **Claude**, fixed rules, or rules because the model did not answer.

## How the brief's must-haves are met

| Must have | How | Proof |
|---|---|---|
| Nothing executes without explicit confirmation | Execution only happens in `Confirmer.confirm`, after a button press or the exact typed word `أكد`. «اوك», «نعم», or a spoken «أكد» don't count. The draft is checked for owner, expiry and a SHA-256 of its payload. | `tests/test_confirm.py`, static AST test |
| Ambiguity → ask, not guess | Deterministic resolvers. Two or more matching contacts or billers, or any non-exact match, always produce a question. | `tests/test_dialogue.py::test_ahmed`, `::test_electricity` |
| Retries never double-pay | The draft UUID is the idempotency key; there is a `(user, key)` unique constraint, and the debit and ledger commit atomically | [eval/idempotency_proof.md](eval/idempotency_proof.md), 50-concurrent-request test |
| Honest failure messages | Each failure has its own Iraqi-Arabic message. An unknown outcome says "checking", never "failed". | [FAILURE_MODES.md](FAILURE_MODES.md) |

The configured LLM only extracts text spans (who, what, how much). It has no wallet tools, and a span that isn't in the user's text is rejected. Everything that touches money is plain code.

## Run

Python 3.11+. On Windows use `./make.ps1 <target>`; elsewhere use `make <target>`.

```sh
python -m venv .venv && .\.venv\Scripts\Activate.ps1   # or: source .venv/bin/activate
python -m pip install -e ".[test]"
make seed      # load the mock wallet (keeps an existing database)
make test      # offline test suite
make eval      # dev test set
make heldout   # held-out test set
make run       # http://localhost:8000
```

- **Free hosted models:** `LLM_PROVIDER=groq` + `GROQ_API_KEY` (default `openai/gpt-oss-120b`), or `LLM_PROVIDER=gemini` + `GEMINI_API_KEY` (default `gemini-3.8-flash`; set `LLM_MODEL` to a Flash-Lite id for higher free volume). Keys come from your own free accounts, kept in `.env`.
- **Local model:** `LLM_PROVIDER=ollama` (default `qwen3.5:4b`). **Claude:** `LLM_PROVIDER=anthropic` + `ANTHROPIC_API_KEY` (paid). Without any of these the offline rule parser is used.
- **LLM-generated demo wallet:** set `DATABASE_URL=sqlite:///demo.db` and `SEED_PATH=data/heldout_seed.json`, then run `make seed` and `make run`.
- **Demo faults:** `DEMO_MODE=true` shows the sidebar faults (lost response, crash before commit, provider down, delay). Fault headers are ignored otherwise.
- Settings are documented in `.env.example`. Export them in your shell; `.env` is not loaded automatically. This is a localhost demo server; don't expose it.

## Architecture

See **[ARCHITECTURE.md](ARCHITECTURE.md)**: runtime path and state diagrams, module map, the seven safety invariants with the code and tests that enforce them, the model layer, and the data and evaluation pipeline.

## Dialect assumptions to verify

- `ميت ألف` / `مية ألف` mean 100,000 IQD; `نص مليون`, `ربع مليون`, `مليون ونص`, `مليونين`, `ألفين` are explicitly supported.
- Bare values below 1,000 without a unit are ambiguous. Explicit `50 دينار` is accepted as 50 IQD. Larger numeric values such as `50000` mean IQD.
- Unknown money slang (`ورقة`, `دفتر`, or malformed separators/decimals) prompts for clarification. No exchange-rate or slang meaning is invented.
- Electricity includes national grid and neighborhood generator unless specified. Fuzzy matches require score >=90 and a >=15 point lead; candidate floor is 80. Non-exact contact matches always require a choice, even above the score threshold. Similar short names can require a choice even on exact spelling.
- Known Arabizi forms `dizz l ahmad 50 alf` and `dizz l khalo 50 alf` are supported; other spellings fail conservatively.
- Top-ups create an unpaid mock invoice for the chosen provider/account and amount. Existing invoices must be paid for their exact recorded amount. Multiple unpaid periods require a period choice.
- A native Iraqi speaker must review wording, names, transliteration, amount words and the test set. No human review is claimed.

## Models and data generation

Default `LLM_PROVIDER=rule` needs no credentials and never contacts a model. Put settings in an untracked `.env` (loaded automatically; shell variables win): `LLM_PROVIDER=groq` + `GROQ_API_KEY`, `gemini` + `GEMINI_API_KEY`, `ollama`, or `anthropic` + `ANTHROPIC_API_KEY` (paid). Whatever the provider, model output passes span checks and falls back to the rule parser; `make eval` also reports the model alone, without that fallback.

**Development vs held-out.** `data/seed.json` + `data/testset.jsonl` (68 requests) are the development set and may be used for tuning. The held-out set is generated once, reviewed, frozen, and never tuned on:

1. `python -m data.generate_mock_data seed` → `data/heldout_seed.json`: the model fills a wallet blueprint; code expands it (`data/synthetic.py`).
2. `python -m data.generate_mock_data testset` → `data/heldout.jsonl`: requests per outcome with the needed labels required, every ID checked against the wallet, batches cached so a rate-limited run resumes.
3. A native speaker hand-edits wording and labels (`hand_edited`, `human_review`), then commits: **that commit is the freeze**. The generator never overwrites.
4. `make heldout` writes `eval/report-heldout*.md`; each report names the test set and its sha256. Only a wrong payment fails the run.

## Tests and evaluation

`make test` / `./make.ps1 test` runs all tests offline. `make eval` runs 68 curated requests three times each with a fresh seeded database and writes [eval/report.md](eval/report.md) and machine-readable [eval/results.json](eval/results.json). Each item only passes if all three runs pass. The report includes unsafe execution, success, clarification, over-asking, split and parser metrics; all failures include expected and actual outcomes.

Only `EXECUTE_AFTER_CONFIRM` evaluation cases are auto-confirmed. ASK and SPLIT cases are not executed; full sequential execution is covered separately by confirmation and HTTP tests. Payee ID, provider ID, type and amount are all checked against fixtures. A negative-control test proves the evaluator detects an intentionally wrong payee expectation.

The JSONL cases were curated by the implementation agent. `hand_edited: true` means individually edited fixtures, **not human/native-speaker approval**; every item records AI review separately from pending native-speaker review. Optional live evaluation writes a separate provider report. The >=95% LLM-parser target and live-provider unsafe-execution rate are unverified without credentials. Offline success is not evidence of open-ended language accuracy.

## Voice stretch

Set `ASR_API_KEY` (and optionally `ASR_MODEL=whisper-1`) to enable the microphone button. Click to record and click again to stop; recording stops after 30 seconds. The server accepts WAV/WebM up to 8 MiB. The hosted adapter follows the [OpenAI transcription API](https://developers.openai.com/api/docs/guides/speech-to-text). It sends audio only when the user records/submits it.

Every response displays the transcript. Unknown confidence, confidence below 90/100, or any uncertain name/amount tokens force the user to type the corrected request. Hosted Whisper JSON does not supply a calibrated confidence, so the default adapter deliberately requests text review. Injected ASR providers can supply confidence/uncertain tokens, but this is not a guarantee of correctness. Even a high-confidence spoken “أكد” cannot execute; only a subsequent button click or exact typed confirmation can.

Real audio was not supplied, so live transcription and microphone hardware were not tested. `MockASR` covers low confidence, misheard names, corrected text, and attempted spoken confirmation. Optional TTS is an interface only and is not enabled.

To evaluate your own recordings, put WAV/WebM files in `data/audio/` and add `manifest.jsonl` entries such as `{"file":"request.wav","testset_id":"iq-001"}`. With `ASR_API_KEY` set, `make eval` runs each through `/voice` three times and adds matched voice/text success and unsafe-execution metrics. Missing credentials/annotations are explicitly reported, never counted as a passing audio evaluation. Do not commit personal audio or credentials.
